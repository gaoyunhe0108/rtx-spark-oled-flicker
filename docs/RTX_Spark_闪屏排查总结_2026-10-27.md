# RTX Spark（ProArt P14）内置 OLED 闪屏 · 排查总结

> 日期：2026-10-26 初版 / **2026-10-27 定稿（v3）** · 机器：ASUS ProArt P14 H7407BA（RTX Spark N1X，ARM64 Win11 26H1）
> 状态：**高度指向内置屏 eDP 省电态（PSR/面板 D3）**——机制判断，未获厂商确认；Windows 层可调项已逐一验证（VRR 无用户开关）
> 版本：v1 本地模型初版 → v2 修正误读 → v3 结论定稿 → **v3.1 复盘修订（核实措辞与证据强度）**

---

## 1. 最终结论（一句话）

**闪屏发生在 Windows 之下：内置 OLED 面板在"有帧/无帧"两种 eDP 省电状态下的亮度不一致。**
鼠标移动、打字等任何产生新帧的输入 → 面板退出自刷新（唤醒态，亮）；停止 → 进入 PSR 自刷新/D3 省电态（暗）。外接显示器不经过 eDP 自刷新机制，所以外接屏天然不闪；更关键是——**接上外接屏后，内置屏本身也不闪了**（见下）。

**关键佐证（2026-10-27 实测）**：接入第二块显示器时（复制模式和扩展模式都试过），**内置屏本身也不再闪烁**——同样是 DWM 合成后的帧，只是多了一个活动输出，说明该省电态仅在"内置屏是唯一活动显示输出"时才会进入。这是**驱动/面板固件层行为**，不是硬件损坏。

## 2. 实测排除表（本机验证，2026-10-27）

| # | 嫌疑 | 实验方法 | 结果 | 判定 |
|---|---|---|---|---|
| 1 | GPU 负载 / DVFS 时钟 | 停掉本地 llama-server（显存 71GB→1.8GB，利用率 2%）后复测 | 照样闪 | ❌ 排除 |
| 2 | 光线传感器自适应亮度 | `powercfg` ADAPTBRIGHT = 0 | 已关闭 | ❌ 排除 |
| 3 | Windows 动态刷新率 DRR | 高级显示器设置：下拉框只有 120/60，「动态刷新率」开关=关 | 未启用 | ❌ 排除 |
| 4 | 可变刷新率 VRR / G-SYNC | 高级显示器设置显示「可变刷新频率：受支持 (30–120 Hz)」，但设置页与 NVIDIA App 均无可切换的 VRR 开关（NVIDIA App 仅有 G-SYNC Compatible 条目，无开关） | 无法切换 | ⚠️ 无法排除，且无用户开关 |
| 5 | 刷新率档位 | 切换固定 60Hz 复测 | **60Hz 照样闪** | ❌ 刷新率整族排除 |
| 6 | HDR | 设置读出「使用 HDR」= 关 | — | ❌ 排除 |
| 7 | 自适应颜色 | 设置读出 = 关 | — | ❌ 排除 |
| 8 | 系统层亮度/DCS 调光 | 动/静各 10-16 秒、每 200ms 采样 WMI 亮度 + Gamma 表 | 亮度恒 66%、Gamma 和恒 25165440 不变 | ❌ 排除（变化在面板层） |
| 9 | 系统日志驱动崩溃 | 近 3 天 nvlddmkm/TDR/DWM 事件 | 无 | ❌ 排除 |
| 10 | "常亮动画"缓解方案 | 自建置顶常亮小点（60fps）常驻 | **闪烁更严重、变成连续不停** | ❌ 反向证据：刷新/省电态抖动被持续喂帧放大 |
| 11 | 外接显示器 | 接外接屏使用 | **完全不闪** | ✅ 定位到内置 eDP 链路 |
| 12 | 第二块显示器同时活动 | **复制模式 + 扩展模式**分别接入，观察内置屏本身 | **内置屏也不闪** | ✅ **关键阳性**：同一帧喂两屏时闪烁消失 → 该省电态只在"内置屏是唯一活动输出"时进入 |
| 13 | **HDMI 诱骗器（EDID 模拟）** | 插入诱骗器（无真实显示器，仅模拟 EDID/链路） | **内置屏不闪** | ✅ 进一步确认：只要 GPU 侧存在第二路活动输出即可抑制，物理屏/虚拟屏不是必需 |

**注册表线索（NVIDIA 显示类键 `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-...}\0000`）**：
- `DP_SKIP_PANEL_D3_IN_PSR = 1`、`RmPanelBlenDsByAuxToPwrOffMs = 400` —— 表明驱动侧存在 PSR/面板 D3 电源路径与面板电源时序参数（**注册表存在该键 ≠ 状态正在生效**，是否进入由运行时条件决定）
- 均为未公开的厂商级参数，**无用户开关**

## 3. 现象与机理对照

| 现象 | PSR/eDP 省电态解释 |
|---|---|
| 深灰底移动鼠标 → 全屏变亮；停下 → 回落 | 新帧触发退出 PSR（亮）；无帧进入 PSR/D3（暗） |
| 打字同样触发 | 同上，任何新帧都触发 |
| 能明显感知的底色是深灰 | 深灰下 APL 低，面板省电态与唤醒态的驱动电压差更易被察觉 |
| 外接显示器不闪 | DP/USB-C 链路没有 PSR/自刷新（仅 eDP 内置屏有） |
| 常亮小点让闪烁变成连续不停 | （推测）持续喂帧使 PSR/D3 反复进出，亮度在两态间持续跳变 |
| Windows 亮度/Gamma 采样不变 | 调节发生在面板内部，Windows 显示栈看不到 |

## 4. 现实方案（按性价比）

1. **日常接外接屏（复制或扩展模式均可）**：内外两屏都不闪，零成本稳定方案；只在“只用笔记本内置屏”的场景会复发
   - 不想接真实显示器时：**HDMI 诱骗器（EDID 模拟器）实测同样有效**，即插即用、无软件风险；代价是 GPU 持续认为有外接输出，功耗可能略升
2. **升级驱动/BIOS**：当前驱动 617.42（2026-09-30，首发批次）、BIOS H7407BA.303（2026-09-22）；PSR/面板电源时序属于驱动+面板固件，新版本可能修复
3. **向厂商反馈**（唯一根治路径）：见同目录报告 `RTX_Spark_OLED闪屏_厂商反馈报告_2026-10-27.md`
4. **可选：BIOS 界面交叉测试**：重启进 BIOS 界面（不加载 Windows 驱动）观察是否闪——
   - BIOS 里也闪 → 面板固件问题（找华硕）
   - BIOS 里不闪 → Windows 驱动问题（找 NVIDIA）
5. **可选：Linux 交叉验证**（同面板、不同驱动栈）：用 ARM Linux 启动盘引导后观察，可给厂商铁证；需要折腾启动盘
6. **实验性尝试（有风险，已备脚本）**：改 `RmFbsrPagedDMA=0` 关掉帧缓冲自刷新（`diag/apply-psr-off.cmd`，自动备份；`revert-psr.cmd` 回滚）。未公开参数，可能黑屏/功耗异常，仅在愿意承担风险且能接受重启验证时尝试；有外接屏可兜底回滚

## 5. 平台级判断（通病可能性）

- RTX Spark 平台 7 款 OLED 笔记本中 **6 款用三星面板**（华硕 ProArt P14/P16、微星 Prestige N16 Flip AI+、惠普 OmniBook Ultra 16/X 14、联想 Yoga Pro 9n），仅戴尔 XPS 16 用 LG 面板（[来源](https://news.pconline.com.cn/2183/21831722.html)）
- 微星 Prestige N16 Flip AI+（同 N1X+三星 OLED+WoA）用户 [LexZeon/spark-refresh-lab](https://github.com/LexZeon/spark-refresh-lab) 报告了同类"输入触发亮度跳变"，仅用动画缓解、未根治
- 本机面板 ATNA40LE04-0：2880×1800 120Hz、VESA DisplayHDR 1000 True Black、VRR 支持 30–120Hz
- **结论**：更像"N1X + 三星 OLED + 当前驱动"的平台级行为，而非单机硬件缺陷

## 6. 硬件风险评估

**低。** 症状规律可复现、无驱动崩溃、外接输出正常、电池循环 2 次新机在保。若慢动作录像出现扫描线/局部撕裂/坏点，才需转售后排查。
